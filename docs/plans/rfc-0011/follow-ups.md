## Found during execution

_(append as tasks discover them — one row each, with the task number that found it)_

| # | Found by | Item |
|---|---|---|
| 3 | T4 | **An unparseable filter bound is dropped silently.** `buildFilterParams` skips a `range` value `parseMoney` cannot read (`"1,"`, `"abc"`) rather than sending it, because the value changes on every keystroke and a 422 mid-type blanks the list. The trade is that a bound left permanently unreadable filters nothing and says nothing. The fix is a per-control validation state showing `MONEY_PARSE_MESSAGE`, which is a `ColumnFilter` change, not a `buildFilterParams` one. |
| 4 | T4 | **`useShows()` fetches on every inventory page load**, even though the Acquired Show column is off by default. Same shape as `useCatalogSets`, so it is consistent rather than novel — but with T4 the page now makes three unconditional support requests (`/locations`, `/catalog/sets`, `/shows`) to populate dropdowns most visits never open. A shared lazy `optionSource` resolver would fix all three at once. |
| 5 | T4 | **The `_actions` column has no filter and is excluded by name** in `admin-inventory-columns.test.ts`'s `NO_FILTER` set, alongside `_image`. A future pinned/synthetic column has to be added to that set by hand or the totality test fails for the wrong reason. A `filterable: false` flag on `InventoryColumnDef` would say it once, in the registry. |
| 6 | T8 | ~~`/admin/unmatched` carries a LOCAL copy of Triage's `CatalogPicker`~~ — **RESOLVED by T11.** `CatalogSearchDialog` now composes the shared `CardSearchPanel` with `onManualEntry` omitted. |
| 10 | T11 | **Market did NOT adopt `CardSearchPanel`**, despite being named in the task doc's caller table. Its search carries three behaviors the shared component does not expose: a server-error state distinguished from "no results" (`describeApiError`, with a retry button — regression-tested against a real 2026-08-07 500 from a missing `dynamodb:Scan` grant), a per-row name-match confidence chip (`getMatchConfidence`), and a watchlist star action alongside the row. Reproducing all three generically would have meant growing `CardSearchPanel`'s API well past "name + number + set + onSelect + onManualEntry" for one caller. Instead Market kept its own search state/fetch/error handling and gained number + set fields directly (new `AdminMarketPage search fields` tests). If a second caller ever needs inline error-with-retry or per-row badges, that is the signal to lift them into `CardSearchPanel` for real rather than duplicating them again. |
| 7 | T8 | **`PriceDisplay` parses money with `parseFloat`** (`components/admin/shared/PriceDisplay.tsx:15`). It is a display-only path so nothing is written wrong today, but `parseFloat("1,300.00")` renders **`$1.00`** — and `CardPickerRow` feeds it a server-formatted string. Nothing currently sends a grouped string, which is why this is a follow-up and not a fix; `formatMoney`/`parseMoney` is the correct pair. |
| 9 | T9 | **`_upsert_catalog_cards_preserving_priced` now writes twice per card on the common (non-preserved) path** — the conditional `put_item`, then a follow-up `update_item` restoring `first_seen_at` from `ReturnValues="ALL_OLD"`. Doubling write cost on the depth-pass write path was accepted to avoid a pre-read reopening the Phase 2.0a race; if this ever shows up in a cost or latency review, the fix is a single conditional `update_item` with a computed `SET` expression instead of a `put_item`, which would fold both writes into one — deferred here because it is a bigger rewrite than T9's scope. |
| 8 | T8 | **The queue has no search or filter box.** Triage has both. At the queue's designed scale (tens of rows) scanning is fine, and adding a search that hits `/inventory/search` per keystroke for a list that short is cost without benefit — but if the parked cohort ever reaches the low hundreds this becomes the first thing to add. |
| 11 | T15 | **"Split" cost-basis mode is permanently disabled**, not implemented. `IncomingLeg` carries no `market_value` for an incoming leg, so there is nothing to split a trade's basis pro-rata against. Real split math needs `IncomingLeg` widened (T14) to carry each card's catalog/market value at the moment it is staged, then `trade-basis.ts` taught to weight the basis pool by that instead of treating Split identically to Transfer. Until then the UI shows the option disabled with a one-line reason (`SPLIT_DISABLED_REASON`) rather than silently misleading. |
| 12 | T15 | **T13's graded-incoming path (a slab added through a trade, committed, and appearing on `/admin/slabs` with its cert intact) was verified only at the unit level** — `deal-session.test.ts`'s "sends graded incoming fields through to the trade API" — not as a live browser walkthrough, because the sandbox this RFC was built in has no running backend/AWS to commit against. Worth a manual pass (owner or an agent with a live environment) before this ships to production; see manual check #8 in `t12-docs-and-verification.md`. |
| 13 | T16 | **`docs/plans/rfc-0008/follow-ups.md` and `docs/plans/rfc-0010/follow-ups.md` still name `/admin/buy/page.tsx` and `/admin/sell/page.tsx`** at specific line numbers, both deleted by this task. Left as-is deliberately — those files are historical records of decisions made at the time, accurate as of when they were written; rewriting them to point at code that didn't exist yet would misrepresent the history.
