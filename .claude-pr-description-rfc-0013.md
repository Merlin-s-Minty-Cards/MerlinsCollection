## Notes

**Two premises in the RESUME-HERE plan turned out to be wrong; both are
corrected in code comments, `CLAUDE.md`, and `claude-progress.txt` rather than
silently worked around:**

1. *"Vault and Show Prep both already proxy through `/inventory/search`"* —
   they don't. Both are bespoke, **unpaginated** endpoints (`/vault`,
   `/show-prep/mispriced`) returning computed fields (`dollar_net`/
   `percent_net`; `delta_pct`/`delta_dollar`) no registry covers. Converting
   them to a server round-trip would only add two backend registries outside
   this RFC's five-table scope, for a result *identical* to sorting the
   already-complete response client-side (no `limit` truncates either
   endpoint, so there's no page boundary for a server sort to protect). Did
   fix a real bug found along the way: Show Prep's client sort used `|| 0`
   for a missing value, sorting it into the *middle* of the range instead of
   last — inconsistent with every backend registry and with
   `lib/vault-sort.ts`. Rewritten onto a new shared `lib/client-table-sort.ts`
   helper (also used by the Market watchlist, same unpaginated-response
   reasoning).
2. *"History's `TransactionGroups` needs a group sort control"* — the file
   named, `frontend/app/(admin)/admin/history/page.tsx`, has no
   `TransactionGroups` usage at all. It only renders on Show Analytics'
   **Daily tab** (`/admin/analytics`). The control now lives there.

**Deploy item found already complete.** The EventBridge schedule was created
2026-08-12 — two days before the RESUME-HERE checkpoint was written — but
`docs/aws-setup.md` was never given the "DONE" line the project's own
convention uses to mark a completed one-time ops action, so the checkpoint
(reading docs, not live AWS state) diagnosed a solved problem as still open.
Verified against live AWS rather than re-run; did not touch
`backend/taskdef.json` (a separate, owner-owned in-progress file).

**Scope corrections against the RFC's illustrative field lists**, each
documented at its own registry/test file: Locations sorts `value`/`label`
(no `item_count` — would need a new inventory-count aggregate, out of scope);
Slabs sorts `cost_basis` (not `buy_price`) and a derived `priced` flag rather
than the raw `market_value`.
